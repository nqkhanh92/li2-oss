# Quik Proximity Marketing Platform

| This doc is generated by Google AI Studio.

## 1. Overview

Quik Proximity Marketing Platform is a comprehensive web application designed to empower businesses to create, manage, and analyze proximity marketing campaigns. It allows users to manage organizations, define campaigns with various content types (URLs, social media links), and deploy them through "touch-points" like QR codes and short links. The platform offers robust analytics to track campaign performance, visitor engagement, and demographics. It features a multi-tenant architecture (organizations), role-based access control, and subscription plan management.

Built with a modern tech stack including Next.js, TypeScript, Supabase, and Casdoor, the platform is designed for scalability and maintainability.

## 5. Setup Instructions

### 5.1. Environment Variables

This project uses encrypted environment files.

1.  You will need an encrypted `.env.development.enc` or `.env.production.enc` file and the corresponding decryption password.
2.  To decrypt (or encrypt), use the `scripts/encode_env.js` script:
    - Decrypt for development: `yarn .env -d -p "YOUR_DECRYPTION_PASSWORD" -dev`
      This will create a `.env.development` file.
    - Decrypt for production: `yarn .env -d -p "YOUR_DECRYPTION_PASSWORD" -production`
      This will create a `.env.production` file.
3.  For local development, after decrypting `.env.development`, copy it to `.env`:
    `cp .env.development .env`

    Key environment variables you'll likely need to configure in your `.env` file:

    ```env
    # Casdoor Configuration
    NEXT_PUBLIC_CASDOOR_ENDPOINT=
    NEXT_PUBLIC_CASDOOR_APP_NAME=
    CASDOOR_CLIENT_ID=
    CASDOOR_CLIENT_SECRET=
    CASDOOR_CERTIFICATE=
    CASDOOR_ORG_NAME=

    # Supabase Configuration
    NEXT_PUBLIC_SUPABASE_URL=
    NEXT_PUBLIC_SUPABASE_ANON_KEY=
    SUPABASE_SERVICE_ROLE_KEY= # For server-side operations

    # Application Configuration
    NEXT_PUBLIC_APP_URL=http://localhost:3000 # Or your deployed URL
    NEXTAUTH_SECRET= # A strong secret for NextAuth.js (if used directly, or for Casdoor JWT signing)
    JWT_SECRET= # For custom JWTs if any

    # Redis Configuration
    REDIS_URL=redis://localhost:6379

    # Shlink Configuration (if applicable)
    SHLINK_BASE_URL= # e.g., https://s.yourdomain.com
    SHLINK_API_KEY=

    # MoMo Payment Gateway (Example)
    MOMO_PARTNER_CODE=
    MOMO_ACCESS_KEY=
    MOMO_SECRET_KEY=
    MOMO_API_ENDPOINT=
    NEXT_PUBLIC_MOMO_REDIRECT_URL=

    # Sentry (Optional)
    SENTRY_DSN=
    NEXT_PUBLIC_SENTRY_DSN= # If client-side Sentry is separate

    # Other
    PORT=3000 # Or 3002 for dev as per docker-compose.dev.yml
    NODE_ENV=development # or production

    # Mautic (for contact form, if used)
    NEXT_PUBLIC_MAUTIC_FORM_ID=
    ```

### 5.2. Database Setup

1.  Ensure your Supabase instance is running.
2.  Apply the database schema. You can use the `supabase/backup-db.sql` or `supabase/dev-db.sql` file.
    Connect to your Supabase database using a PostgreSQL client (e.g., `psql`, DBeaver, Supabase Studio SQL Editor) and run the contents of the SQL file.
    Example using Supabase CLI (if you have it installed and project linked):
    ```bash
    psql -h AWS_ENDPOINT -p DB_PORT -U postgres -f supabase/dev-db.sql dbname
    ```
    Or directly in the Supabase Studio SQL Editor.
3.  Generate TypeScript types from your Supabase schema:
    ```bash
    yarn db-types
    ```
    This will update `src/types/database.types.ts`.

### 5.3. Authentication Setup (Casdoor)

1.  Set up a Casdoor instance.
2.  Create an "Application" in Casdoor corresponding to this project.
3.  Note the `Client ID`, `Client Secret`, and the public certificate.
4.  Ensure the redirect URIs in Casdoor are configured correctly (e.g., `http://localhost:3000/api/auth/callback`).
5.  Configure the Casdoor endpoint, app name, org name, client ID, client secret, and certificate in your `.env` file.

### 5.4. Install Dependencies

    ```

### 5.5. Run Locally

    ```
    The application should be available at `http://localhost:3000` (or the port specified in your `.env` or `PORT` environment variable).

## 10. Usage Examples (Conceptual)

1.  **User Onboarding:**
    - A new user visits the platform and signs up/logs in via Casdoor.
    - Upon first login, they might be prompted to create an organization or join an existing one if invited.
2.  **Creating a Campaign & Touch-Point:**
    - User navigates to their organization's dashboard.
    - Goes to "Campaigns" -> "Create Campaign". Fills in campaign name, and sets content (e.g., a URL to their product page).
    - Goes to "Touch-Points" -> "Create Touch-Point".
    - Names the touch-point, selects "QR Code" as a variant, and links it to the newly created campaign.
    - The system generates a short URL and a QR code. The user can download the QR code.
3.  **Tracking Visits:**
    - A customer scans the QR code, which redirects them to the campaign's URL via the short link.
    - The platform records this visit, capturing data like OS, browser, location (if available), and referrer.
4.  **Viewing Analytics:**
    - The user visits the "Analytics" section.
    - They can see overall visit counts, breakdowns by device type, location on a map, and performance of different touch-points or tags.
5.  **Inviting a Team Member:**
    - An organization owner goes to "Settings" -> "Organization" -> "Members".
    - Clicks "Invite Member", enters the email and assigns a role (e.g., "Editor").
    - The invited user receives an email and can accept the invitation to join the organization.
